# Configuration Guide (`testform.yml`)

The `testform.yml` file is the master configuration file for your Testform workspace. It declares the active Provider, storage backends, convention policies, and project mappings.

---

## Complete Reference `testform.yml`

```yaml
version: "1.0"

# Active Provider configuration (dictionary format or provider: local)
provider:
  github:
    owner: "my-organization"
    repository: "web-app"
    tokenEnv: "GITHUB_TOKEN"
    projectId: "PVT_kwDOB12345"  # Optional: GitHub Projects V2 Node ID

# Remote State Backend (defaults to 'local' if omitted)
backend:
  type: s3
  bucket: "my-testform-states"
  key: "environments/production/testform.state"
  region: "us-east-1"
  dynamodb_table: "testform-locks"

# Custom fields schema and validation policies
fields:
  milestone:
    type: string
    required: false
  priority:
    type: string
    enum: ["Low", "Medium", "High", "Critical"]
    default: "Medium"
  automated:
    type: boolean
    default: false

# Scope-specific configuration: identity matching, conventions, and directories
scopes:
  testcase:
    identity: "tc-*"
    convention: "{slug}.case.feature"
    output_dir: "./tests/cases"
  testrun:
    identity: "tr-*"
    convention: "{YYYYMMDD}_{HHmmss}.run.feature"
    output_dir: "./tests/runs"
  testplan:
    identity: "tp-*"
    convention: "{slug}.plan.feature"
    output_dir: "./tests/plans"
```

---

## Configuration Blocks

### `provider` Block
Allows declaring the remote provider in structured dictionary format or local mode:
- `github:` or `gitlab:`: Provider configuration block with credentials and repository coordinates (`owner`, `repository`, `tokenEnv`, etc.).
- `local`: Direct `provider: local` scalar declaration to operate only on local state without cloud sync.
- `custom:`: For user-registered custom provider adapters.

### `scopes` Block
Configures rules for each tier of the TaC hierarchy (`testcase`, `testrun`, `testplan`):
- `identity`: Match pattern for the mandatory identity tag (defaults to `tc-*`, `tr-*`, and `tp-*`). `match:` is also accepted.
- `convention`: Automated file naming pattern used by scaffolding utilities (`{slug}`, `{YYYYMMDD}_{HHmmss}`).
- `output_dir`: Default directory where files are placed or scaffolded.

### `backend` Block
Configures state persistence and distributed locking:
- `local`: Writes `./testform.state` to the local filesystem.
- `s3`: AWS S3 with DynamoDB state locks.
- `azurerm`: Azure Blob Storage with Blob Lease locking.
- `gcs`: Google Cloud Storage with atomic generation matching.

### `fields` Block
Defines the schema of allowed custom fields extracted from Gherkin step variables (`* key = value`). Testform validates field types and enums during `testform validate`.
