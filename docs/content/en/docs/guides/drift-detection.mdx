# Drift Detection and Alerts

Continuously monitor whether test cases in external QA systems have been altered out-of-band without Git commits.

## What is Drift?

Drift occurs when a team member modifies a test title, description, or priority directly within the Jira or GitHub web UI, bypassing Git peer review and Pull Request workflows.

## Automated Scheduled Scans in CI/CD

Configure a scheduled nightly cron job in GitHub Actions or GitLab CI executing:

```bash
testform plan -detailed-exitcode -refresh=true
```

- If exit code is `0`: No drift detected; Git and remote systems are completely aligned.
- If exit code is `2`: Drift detected. The pipeline can alert the QA team via Slack or open a security triage issue.

## Enforcing Authoritative State

To eliminate out-of-band changes and reinstate Git specifications:

```bash
testform apply -auto-approve
```

Testform overwrites the unauthorized remote mutations with the version declared in Git, preserving your repository as the **single source of truth**.
