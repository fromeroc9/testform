# Configure Providers

**Providers** in Testform are decoupled modular plugins that connect declarative BDD test specifications with **quality management and state platforms** (GitHub Issues / Projects, GitLab, Jira, or Local Ledger).

Just as in Terraform a provider manages communication with cloud APIs (AWS, Azure, GCP) to record infrastructure state, in Testform a provider manages communication with the issue tracker or state storage to **create, update, close, and version test cases and execution runs as code in Git**.

<Callout type="warning">
**Key Difference: Providers vs Test Runners**  
- **Provider (`provider`):** Traceability and management platform hosting test cases and the state ledger (`local`, `github`, `gitlab`, `jira`).  
- **Test Runner:** Automation tool that executes test code in browsers, APIs, or sockets (`Playwright`, `Cypress`, `Supertest`, `K6`).
</Callout>

---

## Declaration in `main.yml`

Providers are configured in the root **`main.yml`** file:

```yaml
# main.yml
testform:
  required_version: ">= 1.0.0"
  backend:
    local:
      path: "./testform.state"

provider:
  github:
    owner: "my-organization"
    repository: "my-web-platform"
    token_env: "GITHUB_TOKEN"
  jira:
    host: "my-company.atlassian.net"
    project_key: "QA"
    email: "qa-team@company.com"
```

## Available Providers

| Provider | Storage Type | Recommended Usage |
|---|---|---|
| **`local`** | Local `testform.state` file | Agile projects, local suites, and offline Git repositories with no external dependencies. |
| **`github`** | GitHub Issues + GitHub Projects (GraphQL) | Teams centralizing specifications and test tracking in GitHub Enterprise / Cloud. |
| **`gitlab`** | GitLab Issues + Scoped Labels | GitLab CI/CD pipelines tracking tests on GitLab issue boards. |
| **Custom Providers** | Registered via `registerResource()` | Custom integrations with proprietary QA platforms, TestRail, or Xray. |

## Provider Initialization (`testform init`)

Before running a plan, `testform init` validates credentials and sets up the workspace:

```bash
testform init
```

During initialization:
1. Verifies access tokens (e.g. `GITHUB_TOKEN` or `GITLAB_TOKEN`).
2. Configures the state backend and creates the state lock file (`.lock`).
3. Verifies repository access and project boards.
