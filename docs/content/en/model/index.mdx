# The Terraform Model in Testform

Testform translates the proven principles of **Infrastructure as Code (IaC)**—pioneered by HashiCorp Terraform—into **Test-as-Code (TaC)**.

Instead of provisioning virtual machines, VPCs, and databases, Testform declaratively provisions and orchestrates **Test Cases, Test Runs, and Test Plans** across Issue Trackers and Test Management systems (such as GitHub Issues, Projects V2, and Jira).

---

## Conceptual Mapping: Terraform vs. Testform

If you understand Terraform, you already understand Testform:

| Terraform Concept | Testform Equivalent | Description |
| :--- | :--- | :--- |
| **Configuration Files (`.tf`)** | **Gherkin Files (`.feature`)** | Declarative specification of desired state. |
| **`terraform.tfstate`** | **`testform.state`** | Single source of truth mapping local declarations to remote IDs. |
| **Providers (`aws`, `azurerm`, `google`)** | **Providers (`github`, `jira`, `gitlab`)** | Adapter plugins communicating with external APIs. |
| **Resource Blocks (`resource "..."`)** | **Scenarios & Rules (`Scenario:`, `Rule:`)** | Units of managed infrastructure. |
| **Attributes & Arguments** | **Gherkin Steps & DSL Variables** | Properties such as title, steps, assignees, milestones. |
| **`terraform plan`** | **`testform plan`** | Speculative diff comparing local specs against remote reality. |
| **`terraform apply`** | **`testform apply`** | Idempotent reconciliation executing planned mutations. |
| **`terraform destroy`** | **`testform destroy`** | Graceful closing or deletion of managed test resources. |
| **`terraform refresh`** | **`testform refresh`** | Pulls current state from remote APIs into local state without applying. |
| **`terraform taint`** | **`testform taint`** | Marks a resource for deletion and recreation on next apply. |
| **`terraform import`** | **`testform import`** | Adopts existing unmanaged remote issues into the state file. |
| **`terraform workspace`** | **`testform workspace`** | Isolates environments (e.g. `staging`, `production`, `release-1.2`). |
| **State Locking** | **Distributed State Locks** | Prevents concurrent applies (DynamoDB, Azure Blob leases, S3, GCS). |

## 1. Declarative Configuration Language

### From HCL to Pure Gherkin

In standard Terraform, you write HashiCorp Configuration Language (HCL). In Testform, you write **standard Gherkin**, preserving 100% compatibility with BDD test runners (Cucumber, Behave, Playwright, Cypress) while functioning as declarative configuration.

#### Terraform HCL Approach (Hypothetical)
```hcl
provider "testform" {
  organization = "my-org"
  repository   = "web-app"
}

resource "testform_testcase" "login_valid" {
  title       = "Login exitoso con credenciales correctas"
  tags        = ["login", "smoke", "high"]
  steps       = [
    "Given el usuario navega a la página de inicio de sesión",
    "When ingresa credenciales válidas",
    "Then el sistema muestra el panel principal"
  ]
  milestone   = "Sprint 42"
  assignees   = ["qa-lead"]
}
```

#### Testform Declarative Gherkin (Actual)
```gherkin
@testcase @login @smoke
Feature: Autenticación de Usuarios

  Background:
    * milestone = "Sprint 42"
    * assignees = "qa-lead"

  @high @tc-1
  Scenario: Login exitoso con credenciales correctas
    Given el usuario navega a la página de inicio de sesión
    When ingresa credenciales válidas
    Then el sistema muestra el panel principal
```

Testform's compiler parses this Gherkin AST and generates an internal resource equivalent to `testform_testcase.login_valid`.
