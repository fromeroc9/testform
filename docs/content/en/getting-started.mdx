# Getting Started with Testform

This guide will walk you through installing Testform, configuring authentication, and provisioning your very first declarative test case in GitHub in under 5 minutes.

---

## Prerequisites

- **Node.js** (v18 or higher)
- A **GitHub Account** and a repository where you have Issue creation permissions.
- Basic familiarity with Gherkin (`.feature`) files.

---

## 1. Installation

Install the official Testform CLI globally via npm:

```bash
npm install -g @fromeroc9/testform
```

Verify your installation:

```bash
testform version
```

---

## 2. Authentication

Testform needs an API token with write permissions to manage issues on your repository. You can configure credentials securely with the built-in `login` command:

```bash
testform login github.com
```
*Paste your GitHub Personal Access Token (PAT) with `repo` and `project` scopes.*

Alternatively, you can export your token in your environment (recommended for CI/CD):
```bash
export GITHUB_TOKEN="ghp_yourPersonalAccessTokenHere"
```

---

## 3. Initialize Your Workspace

Create a new directory for your tests and initialize Testform:

```bash
mkdir my-testing-suite
cd my-testing-suite
testform init
```

This creates a default `testform.yml` file. Open it and update the Provider block with your repository coordinates:

```yaml
version: "1.0"

provider:
  type: github
  config:
    owner: "your-github-username"
    repository: "your-repository-name"
    tokenEnv: "GITHUB_TOKEN"
```

---

## 4. Write Your First Test Case

Create a new file named `tests/auth.case.feature`:

```gherkin
@testcase @auth
Feature: Authentication Tests

  Background:
    * milestone = "Sprint 1"
    * assignees = "your-github-username"

  @smoke @tc-1
  Scenario: Successful login with valid credentials
    Given the user navigates to "/login"
    When the user enters valid credentials
    Then the user is redirected to "/dashboard"
```

*Key details:*
- `@testcase`: Declares this file as a test case specification.
- `@tc-1`: Permanent identity tag linking this scenario to its GitHub Issue (similar to a resource logical name in Terraform). Required by the `identity-required` policy to guarantee resource persistence and enable referencing in `testruns`.

---

## 5. Plan Your Changes (`plan`)

Run `testform plan` to see what Testform proposes to do without modifying GitHub:

```bash
testform plan
```

Output:
```text
Testform will perform the following actions:

  # tests/auth.case.feature::@tc-1 will be created
  + resource "testcase" "successful_login" {
      + title     = "Successful login with valid credentials"
      + labels    = ["auth", "smoke"]
      + milestone = "Sprint 1"
      + state     = "open"
    }

Plan: 1 to add, 0 to change, 0 to destroy.
```

---

## 6. Apply Your Changes (`apply`)

Execute the plan to create the actual GitHub Issue:

```bash
testform apply
```

When prompted, type `yes`:
```text
Do you want to perform these actions?
  Only 'yes' will be accepted to approve.

  Enter a value: yes

testcase.successful_login: Creating...
testcase.successful_login: Creation complete after 1s [id=1]

Apply complete! Resources: 1 added, 0 changed, 0 destroyed.
```

Navigate to your GitHub repository: you will see **Issue #1** created with the title, labels (`auth`, `smoke`), milestone (`Sprint 1`), assignees, and formatted Gherkin steps!
