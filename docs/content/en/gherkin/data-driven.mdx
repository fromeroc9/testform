# Data-Driven Testing (Examples & Data Tables)

Testform fully supports parameterized, data-driven tests through Gherkin's `Scenario Outline` and `Data Tables`.

---

## `Scenario Outline` with `Examples:`

When testing the same workflow against multiple data variations, use `Scenario Outline`:

```gherkin
@testcase @validation
Feature: User Input Validation

  Scenario Outline: Email validation with different formats
    Given the user is on the registration page
    When the user enters email "<email>"
    Then the input field should be marked as "<status>"

    Examples:
      | email              | status  |
      | valid@test.com     | valid   |
      | missing-at.com     | invalid |
      | user@domain..com   | invalid |
      | test+label@co.org  | valid   |
```

### How Testform Handles Scenario Outlines:
Testform's compiler evaluates the table and generates parameterized variations:
1. Formats the `Examples:` table into a clean GitHub Markdown table within the issue description.
2. Tracks the scenario outline as an atomic unit with its parameter table preserved for automation runs.

---

## Step Data Tables

Step data tables allow passing structured datasets into a single step:

```gherkin
Scenario: Create a batch of user accounts
  Given the administrator creates the following users:
    | username | role       | department  |
    | alice    | admin      | DevOps      |
    | bob      | developer  | Engineering |
    | carol    | auditor    | Security    |
  Then all 3 accounts are active in the directory
```

Testform formats step data tables with proper monospace alignment and borders inside the generated issue body.

---

## Doc Strings (`"""`)

For multi-line text payloads, JSON configurations, or SQL queries, use Doc Strings:

```gherkin
Scenario: Verify web hook payload delivery
  When the service receives a POST request with payload:
    """json
    {
      "event": "order.completed",
      "order_id": "ORD-9912",
      "currency": "USD",
      "amount": 149.99
    }
    """
  Then the response status code is 200
```
Testform preserves syntax highlighting tags (e.g. `"""json`) when rendering the issue in GitHub.
