# Reusable Modules (`@module`)

> [!WARNING]
> **Experimental Feature (Tech Preview):** The `@module` directive is an experimental capability under active development. The import syntax, step composition rules, and scenario resolution mechanisms are subject to change in upcoming releases.

In enterprise test suites with extensive workflows (E2E, integration, and regression suites), Quality Engineering teams frequently need to reuse step sequences or complete scenarios for authentication, data setup, and teardown.

The `@module` directive allows you to import and embed steps from external `.case.feature` files directly into your BDD specifications without code duplication.

---

## 1. Usage Scopes

The `@module` directive can be declared at two levels:
1. **Scenario Level (`Scenario`)**: To inject steps from a reusable scenario directly into an individual testcase.
2. **Feature Level (`Feature`)**: To compose cumulative suites or import entire feature flows.

---

## 2. Invoking Specific Scenarios

When the source module file contains multiple scenarios, you can target an exact scenario by specifying its identity using two supported syntaxes:

### Syntax A: Double-Colon Selector (`::`)
```gherkin
@testcase
Feature: Checkout and Payment Process

  @smoke @tc-checkout-1
  @module(source="./auth.case.feature::tc-login")
  Scenario: Successful credit card payment
    # Steps from scenario @tc-login in auth.case.feature execute first
    When the user selects "Credit Card"
    And submits valid card details
    Then the order is confirmed
```

### Syntax B: Explicit Parameter `id="..."`
```gherkin
@testcase
Feature: User Profile Management

  @tc-profile-1
  @module(source="../common/auth.case.feature", id="tc-login")
  Scenario: Updating user password
    When the user updates their password
    Then a confirmation email is dispatched
```

---

## 3. Full Feature Module Import

If you omit the scenario identifier, Testform imports all steps from the target module file:

```gherkin
@testcase
Feature: End-to-End Purchase Flow

  @tc-full-purchase
  @module(source="../modules/cart-setup.case.feature")
  Scenario: Online order completion
    When the user confirms the purchase
    Then the order status transitions to "Completed"
```

---

## 4. Path Resolution

Testform resolves module paths relative to the current `.feature` file declaring the directive, or relative to the workspace root defined in `testform.yml`.

> [!TIP]
> **Best Practice:** Keep reusable atomic cases organized in a dedicated directory (e.g., `testcases/common/`) with explicit `@tc-*` identity tags.
