# State Migration Guide

As your team evolves from single-developer prototyping to collaborative production pipelines, you will need to migrate your state from the `local` backend to a remote cloud backend (AWS S3, Azure Blob, or Google Cloud Storage).

Testform provides built-in automated state migration with safety verification.

---

## Step-by-Step Migration Workflow

### Step 1: Update `testform.yml`
Edit `testform.yml` and add your desired remote backend configuration:

```yaml
# Before:
# backend:
#   type: local

# After:
backend:
  type: s3
  config:
    bucket: "production-testform-states"
    key: "app/testform.state"
    region: "us-east-1"
    dynamodb_table: "testform-locks"
```

---

### Step 2: Run `testform init -migrate-state`

Execute `init` with the `-migrate-state` flag:

```bash
$ testform init -migrate-state

Initializing the backend...

Backend configuration changed!

Testform has detected you're changing your backend configuration from "local" to "s3".

Do you want to copy existing state to the new backend?
  Pre-existing state was found while migrating the previous "local" configuration to the
  new "s3" configuration. No existing state was found in the newly configured "s3" backend.
  Do you want to copy this state to the new "s3" backend? Enter "yes" to confirm and "no"
  to start with an empty state.

  Enter a value: yes

Copying state from "local" to "s3"...
State copied successfully!

Successfully configured the backend "s3"! Testform will automatically
use this backend unless the backend configuration changes.
```

---

### Step 3: Verify Migration with `testform state list`

Run `testform state list` to confirm that all resources are visible in the new remote backend:

```bash
testform state list
```

---

### Step 4: Archive Local State File

Once verified, you can safely remove the local `./testform.state` file or add it to `.gitignore` so developers do not accidentally read stale local files:

```bash
rm testform.state
```
