# State Architecture & Concepts

Testform records information about the infrastructure it creates in a state file. By default, when running locally, this state is stored in a file named `testform.state`.

This file acts as the single source of truth connecting your local `.feature` files to the actual remote issues, checklists, and project cards in GitHub or Jira.

---

## Anatomy of the State File

The `testform.state` file uses a structured JSON format versioned identically to Terraform:

```json
{
  "version": 4,
  "testform_version": "1.0.17",
  "serial": 18,
  "lineage": "9b6c085b-8664-4bf8-b805-4c07a3c3328e",
  "resources": [
    {
      "scope": "testcase",
      "type": "github_testcase",
      "name": "login_valid",
      "identity": "login.case.feature::@tc-1",
      "provider": "provider.github",
      "instances": [
        {
          "attributes": {
            "id": 104,
            "number": 104,
            "title": "Valid credentials allow login",
            "url": "https://github.com/my-org/web-app/issues/104",
            "localHash": "a3f5c71d8e20b3...",
            "tainted": false
          }
        }
      ]
    }
  ]
}
```

### State Fields Explained
- **`version`**: Schema version format (`4`).
- **`serial`**: Monotonically increasing counter incremented on every successful state mutation. Prevents older state snapshots from overwriting newer ones.
- **`lineage`**: Unique UUID assigned when the state was first created. Guarantees that two completely distinct projects never accidentally overwrite one another.
- **`identity`**: Unique key binding local code to state (`[filename]::@tc-1` or configured identity pattern in `testform.yml`).
- **`localHash`**: SHA-256 hash of the local scenario content used to bypass unnecessary API updates.

---

## State Locking & Concurrency

When multiple developers or CI/CD pipelines run `testform apply` at the same time against the same repository, they risk race conditions that could create duplicate issues or corrupt state.

Testform prevents this with **Distributed State Locking**:
- Acquires an exclusive mutex lock before reading or planning.
- If a lock is held by another process, Testform outputs the lock owner's ID and halts.
- Releases the lock atomically once all mutations are recorded.
