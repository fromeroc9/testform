# Backend: Azure Blob Storage

The `azurerm` backend stores Testform state in Microsoft Azure Blob Storage. It natively uses Azure **Blob Leases** for zero-dependency distributed state locking.

---

## Configuration

In `testform.yml`:

```yaml
backend:
  type: azurerm
  config:
    resource_group_name: "rg-testform-shared"
    storage_account_name: "satestformshared"
    container_name: "testform-states"
    key: "web-app/production.testform.state"
```

---

## Authentication

Testform supports all standard Azure authentication mechanisms:
1. **Azure CLI**: Automatic login via `az login`.
2. **Environment Variables**:
   - `ARM_CLIENT_ID`
   - `ARM_CLIENT_SECRET`
   - `ARM_TENANT_ID`
   - `ARM_SUBSCRIPTION_ID`
3. **Managed Service Identity (MSI)**: When running inside Azure DevOps agents or Azure VMs.
4. **SAS Token**: Passed dynamically during initialization:
   ```bash
   testform init -backend-config="sas_token=?sv=2024-01-01&..."
   ```

---

## Native Blob Leases

Unlike AWS (which requires a separate DynamoDB table), Azure Blob Storage provides native 60-second renewable blob leases. Testform acquires an exclusive write lease whenever `apply` or `state` operations execute.
