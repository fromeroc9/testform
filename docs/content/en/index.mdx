### 1. Local Specification (Git)
`tests/features/auth.case.feature`

```gherkin
Feature: User Authentication and Access
  As a registered user of the platform
  I want to authenticate with valid credentials
  In order to access the protected dashboard

  Background:
    * field automate = apply

  @high @tc-login-001
  Scenario: Successful login with valid credentials
    Given the user navigates to "/login"
    When the user enters email "admin@company.com"
    And the user enters temporary password "Secret123!"
    And clicks the "Sign In" button
    Then the browser redirects to "/dashboard"
    And the banner displays "Welcome, Administrator"
```

## Traditional QA vs Testform (Test-as-Code)

| Dimension | Traditional Approach | Testform (Test-as-Code) |
| :--- | :--- | :--- |
| **Storage** | Spreadsheets or disconnected web interfaces. | Git-versioned `.feature` files living alongside application code. |
| **Peer Review** | Untracked or informal comments. | Pull Requests, branch protection, and speculative diff reviews. |
| **Traceability** | Decoupled from releases and commits. | Exact mapping to Git commit SHA and release tags. |
| **Concurrency** | Silent overwrites and race conditions. | Distributed state mutex locks with cryptographic leases. |
| **Automation** | Fragmented scripts disconnected from test cases. | Native orchestration with Playwright, Vitest, and Cypress. |

## Get Started in Three Steps

### 1. Global Installation

```bash
npm install -g @fromeroc9/testform
```

### 2. Initialize Workspace

```bash
testform init
```

### 3. Plan and Reconcile

```bash
testform plan
testform apply -auto-approve
```
