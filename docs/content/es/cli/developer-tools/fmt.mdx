# `testform fmt`

```bash
testform fmt [opciones] [directorio-objetivo]
```

El comando `testform fmt` formatea y reescribe los archivos Gherkin `.feature` para ajustarlos a las pautas de estilo canónicas. Normaliza la indentación, alinea las palabras clave de los pasos (`Given`/`When`/`Then`), formatea las tablas de datos y elimina espacios en blanco al final de las líneas.

## Opciones del Comando

| Opción | Por Defecto | Descripción |
| :--- | :--- | :--- |
| `-check` | `false` | Comprueba si los archivos están formateados sin modificarlos en disco. Devuelve código de salida `3` si detecta cambios necesarios (ideal para linters de CI). |
| `-diff` | `false` | Muestra diffs unificados con los cambios de formateo aplicables. |
| `-recursive` | `true` | Formatea de forma recursiva todos los subdirectorios. |

## Ejemplo de Ejecución Real

```bash
$ testform fmt
tests/auth/login.case.feature
tests/checkout/cart.case.feature

2 files reformatted.
```

## Modo Linter para CI/CD (`-check`)

En los flujos automatizados de revisión de Pull Requests, ejecuta:
```bash
testform fmt -check
```
Si algún desarrollador introdujo archivos Gherkin sin formatear, el comando finaliza con código de error `3` e imprime las rutas de los archivos afectados.

## Códigos de Salida

- `0`: Todos los archivos formateados correctamente (o ya formateados al usar `-check`).
- `1`: Error al procesar los archivos.
- `3`: Se requieren cambios de formato (únicamente al ejecutar con `-check`).
