# `testform force-unlock`

```bash
testform force-unlock [opciones] <id-bloqueo>
```

El comando `testform force-unlock` elimina forzosamente un bloqueo distribuido de estado que haya quedado huérfano o bloqueado en el espacio de trabajo actual.

## Cuándo Utilizar `force-unlock`

El bloqueo de estado previene que dos miembros del equipo o pipelines de CI muten el estado simultáneamente. Sin embargo, si un runner de CI colapsa abruptamente, se corta la energía o se finaliza el proceso (`kill -9`), el bloqueo puede permanecer retenido en DynamoDB, Azure Blob leases o GCS, impidiendo la ejecución de comandos posteriores:

```
Error: Error acquiring the state lock
  Lock Info:
    ID:        b7c93e41-0f82-498b-9d22-123456789abc
    Path:      mi-bucket/testform.state
    Owner:     ci-runner-ip-10-0-2-44
    Created:   2026-10-19 15:20:00 UTC
```

## Opciones del Comando

| Opción | Por Defecto | Descripción |
| :--- | :--- | :--- |
| `-force` | `false` | Omite la confirmación interactiva antes de desbloquear. |

## Ejemplo de Ejecución Real

```bash
$ testform force-unlock b7c93e41-0f82-498b-9d22-123456789abc

Do you really want to force-unlock?
  Testform will remove the lock on the current state.
  Please ensure that no other process is actively running against this state.

  Enter a value: yes

Testform state lock b7c93e41-0f82-498b-9d22-123456789abc successfully released!
```

## Advertencia: Riesgos de Concurrencia

Utiliza `force-unlock` únicamente tras verificar con total certeza que el proceso que originó el bloqueo ya no se encuentra en ejecución. Liberar un estado mientras un comando apply está activo puede generar corrupción irreversible en el archivo de estado.

## Códigos de Salida

- `0`: Bloqueo liberado exitosamente.
- `1`: ID de bloqueo no válido o error de comunicación con el backend.
