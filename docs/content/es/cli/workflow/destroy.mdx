# `testform destroy`

```bash
testform [opciones globales] destroy [opciones]
```

El comando `testform destroy` es un atajo directo para `testform apply -destroy`. Destruye (cierra o purga) todos los recursos remotos registrados en el archivo de estado para el alcance indicado, sin borrar tus archivos locales `.feature`.

## Opciones del Comando

| Opción | Por Defecto | Descripción |
| :--- | :--- | :--- |
| `-auto-approve` | `false` | Omite la confirmación interactiva antes de proceder a la destrucción. |
| `-target=address` | — | Limita la destrucción a una única instancia de recurso (por ejemplo: `login.case.feature::@tc-1`). |
| `-lock=false` | `true` | Desactiva el bloqueo de estado durante la destrucción. |
| `-no-color` | `false` | Desactiva los colores en la salida. |
| `-json` | `false` | Emite los eventos de destrucción en formato JSON. |

## Ejemplo de Ejecución Real

```bash
$ testform destroy -scope=testcase

Testform will perform the following actions:

  # login.case.feature::@tc-1 will be destroyed
  - resource "testcase" "login_valid" {
      - id        = 104
      - title     = "Valid credentials allow login"
    }

Plan: 0 to add, 0 to change, 1 to destroy.

Do you really want to destroy all resources?
  Testform will destroy all your managed infrastructure, as shown above.
  There is no undo. Only 'yes' will be accepted to confirm.

  Enter a value: yes

testcase.login_valid: Destroying... [id=104]
testcase.login_valid: Destruction complete after 1s

Destroy complete! Resources: 1 destroyed.
```

## Destrucción Dirigida de Recursos Específicos

Para destruir un escenario aislado sin perjudicar al resto de la suite de pruebas:

```bash
testform destroy -target="auth.case.feature::@tc-2"
```

## Códigos de Salida

- `0`: Todos los recursos seleccionados se destruyeron satisfactoriamente.
- `1`: Ocurrió un error durante la destrucción.
