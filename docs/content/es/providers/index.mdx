# Arquitectura de Providers

Al igual que Terraform depende de los providers para interactuar con las APIs en la nube como AWS, Azure y Cloudflare, **Testform depende de los Providers** para comunicarse con gestores de incidencias, tableros de gestión de proyectos y plataformas de ejecución de pruebas.

---

## Qué Hace un Provider

Un Provider es un plugin adaptador que implementa la interfaz de Provider de Testform:
1. **Autenticación**: Administra tokens de API, sesiones OAuth o credenciales seguras.
2. **Operaciones CRUD sobre Recursos**: Convierte las operaciones de recursos de Testform en llamadas a APIs remotas:
   - `create`: Invoca endpoints de creación de incidencias (REST / GraphQL).
   - `read`: Recupera el estado en vivo de incidencias, etiquetas y tarjetas de proyecto para la detección de desviaciones (drift).
   - `update`: Ejecuta actualizaciones in-place modificando únicamente los campos cambiados.
   - `delete`: Cierra o elimina tickets remotos.
3. **Mapeo de Atributos**: Transforma variables de paso del DSL de Gherkin (`* milestone`, `* assignees`) en identificadores internos de entidades remotas.

---

## Providers Disponibles

- **[Provider Oficial de GitHub](./github)**: Integración nativa con GitHub Issues, Milestones y Projects V2.
- **[Providers Personalizados](./custom)**: Framework de extensibilidad para desarrollar integraciones con Jira, GitLab, TestRail o Azure DevOps.
- **[Automatización CI/CD](./ci-cd)**: Ejecución automatizada de Testform en flujos de trabajo de GitHub Actions.
