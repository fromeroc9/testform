## Flujo de Trabajo Declarativo en Accion

Observa como una especificacion Gherkin versionada en Git se traduce en un plan de conciliacion reproducible y de solo lectura.

### 1. Especificacion Local (Git)
`tests/features/auth.case.feature`

```gherkin
Feature: Funcionalidad de Autenticacion y Acceso
  Como usuario registrado de la aplicacion
  Quiero autenticarme con credenciales validas
  Para acceder al panel de control protegido

  Background:
    * field automate = apply

  @high @tc-login-001
  Scenario: Inicio de sesion exitoso con credenciales validas
    Given el usuario navega a la URL "/login"
    When introduce el correo "admin@empresa.com"
    And introduce la contrasena temporal "Secret123!"
    And pulsa el boton "Iniciar Sesion"
    Then el sistema debe redirigir a "/dashboard"
    And el banner muestra "Bienvenido, Administrador"
```

</div>

### 2. Plan de Conciliacion Especulativo
`testform plan`

```text
Testform v1.0.17
Backend configurado: local (testform.state)
Adquiriendo bloqueo de estado... Bloqueo adquirido.

Calculando grafo de dependencias y plan de conciliacion:

  + resource "testcase" "tests/features/auth.case.feature::@tc-login-001" {
      + title       = "Inicio de sesion exitoso con credenciales validas"
      + feature     = "Funcionalidad de Autenticacion y Acceso"
      + priority    = "high"
      + automate    = "apply"
      + steps_count = 6
      + status      = "draft"
    }

Plan: 1 para agregar, 0 para cambiar, 0 para destruir.
Liberando bloqueo de estado... Bloqueo liberado.
```

## Enfoque Tradicional vs Test-as-Code

| Capacidad | Enfoque Tradicional | Testform (Test-as-Code) |
| :--- | :--- | :--- |
| **Almacenamiento** | Hojas de calculo o interfaces web lentas fuera del codigo. | Archivos `.feature` versionados en Git junto al codigo fuente. |
| **Revision de Cambios** | Sin trazabilidad o mediante comentarios aislados. | Pull Requests, revision por pares y diffs especulativos. |
| **Trazabilidad** | Desconectada de commits y ramas de funcionalidad. | Vinculacion estricta por SHA de commit y releases. |
| **Concurrencia** | Conflictos y sobreescrituras silenciosas. | Bloqueo distribuido de estado con mutex y leases criptograficos. |
| **Automatizacion** | Dispersa en scripts sin conexion con los casos de prueba. | Orquestacion nativa con Playwright, Vitest y Cypress. |

## Comienza en Tres Pasos

### 1. Instalacion Global

```bash
npm install -g @fromeroc9/testform
```

### 2. Inicializacion del Espacio de Trabajo

```bash
testform init
```

### 3. Planificacion y Conciliacion

```bash
testform plan
testform apply -auto-approve
```
