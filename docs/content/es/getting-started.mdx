# Primeros Pasos con Testform

Esta guía te acompañará paso a paso para instalar Testform, configurar la autenticación y aprovisionar tu primer caso de prueba declarativo en GitHub en menos de 5 minutos.

---

## Prerrequisitos

- **Node.js** (v18 o superior)
- Una **Cuenta de GitHub** y un repositorio donde tengas permisos para crear incidencias (Issues).
- Conocimientos básicos sobre archivos Gherkin (`.feature`).

---

## 1. Instalación

Instala la CLI oficial de Testform globalmente mediante npm:

```bash
npm install -g @fromeroc9/testform
```

Verifica la instalación:

```bash
testform version
```

---

## 2. Autenticación

Testform requiere un token de API con permisos de escritura para gestionar issues en tu repositorio. Puedes configurar las credenciales de forma segura con el comando integrado `login`:

```bash
testform login github.com
```
*Pega tu Personal Access Token (PAT) de GitHub con los scopes `repo` y `project`.*

Alternativamente, puedes exportar tu token como variable de entorno (recomendado para CI/CD):
```bash
export GITHUB_TOKEN="ghp_tuPersonalAccessTokenAqui"
```

---

## 3. Inicializar el Espacio de Trabajo

Crea un directorio para tus pruebas e inicializa Testform:

```bash
mkdir mi-suite-de-pruebas
cd mi-suite-de-pruebas
testform init
```

Este comando genera un archivo base `testform.yml`. Ábrelo y configura el bloque del Provider con las coordenadas de tu repositorio:

```yaml
version: "1.0"

provider:
  type: github
  config:
    owner: "tu-usuario-o-organizacion"
    repository: "nombre-de-tu-repositorio"
    tokenEnv: "GITHUB_TOKEN"
```

---

## 4. Escribir tu Primer Caso de Prueba

Crea un archivo llamado `tests/auth.case.feature`:

```gherkin
@testcase @auth
Feature: Pruebas de Autenticación

  Background:
    * milestone = "Sprint 1"
    * assignees = "tu-usuario-github"

  @smoke @tc-1
  Scenario: Inicio de sesión exitoso con credenciales válidas
    Given el usuario navega a "/login"
    When el usuario ingresa credenciales válidas
    Then el usuario es redirigido a "/dashboard"
```

*Detalles clave:*
- `@testcase`: Declara este archivo como una especificación de caso de prueba.
- `@tc-1`: Etiqueta de identidad permanente que vincula este escenario con su Issue en GitHub (funciona como el identificador lógico de un recurso en Terraform). Requerida por la policy `identity-required` para garantizar la persistencia del recurso y permitir su referencia en `testruns`.

---

## 5. Planificar los Cambios (`plan`)

Ejecuta `testform plan` para inspeccionar las acciones propuestas por Testform sin modificar GitHub:

```bash
testform plan
```

Salida esperada:
```text
Testform will perform the following actions:

  # tests/auth.case.feature::@tc-1 will be created
  + resource "testcase" "successful_login" {
      + title     = "Inicio de sesión exitoso con credenciales válidas"
      + labels    = ["auth", "smoke"]
      + milestone = "Sprint 1"
      + state     = "open"
    }

Plan: 1 to add, 0 to change, 0 to destroy.
```

---

## 6. Aplicar los Cambios (`apply`)

Ejecuta el plan para crear el Issue real en GitHub:

```bash
testform apply
```

Cuando el sistema solicite confirmación, escribe `yes`:
```text
Do you want to perform these actions?
  Only 'yes' will be accepted to approve.

  Enter a value: yes

testcase.successful_login: Creating...
testcase.successful_login: Creation complete after 1s [id=1]

Apply complete! Resources: 1 added, 0 changed, 0 destroyed.
```

Navega a tu repositorio en GitHub: ¡verás el **Issue #1** creado con su título, etiquetas (`auth`, `smoke`), milestone (`Sprint 1`), asignados y los pasos Gherkin formateados!
