# Guía de Configuración (`testform.yml`)

El archivo `testform.yml` es el archivo maestro de configuración de tu espacio de trabajo de Testform. En él se declaran el Provider activo, los backends de almacenamiento de estado, las políticas de convenciones y el mapeo de proyectos.

---

## Archivo de Referencia Completo `testform.yml`

```yaml
version: "1.0"

# Configuración del Provider activo (formato diccionario o provider: local)
provider:
  github:
    owner: "mi-organizacion"
    repository: "aplicacion-web"
    tokenEnv: "GITHUB_TOKEN"
    projectId: "PVT_kwDOB12345"  # Opcional: Node ID de GitHub Projects V2

# Backend para el Estado Remoto (por defecto 'local' si se omite)
backend:
  type: s3
  bucket: "mis-estados-testform"
  key: "entornos/produccion/testform.state"
  region: "us-east-1"
  dynamodb_table: "testform-locks"

# Esquema de campos personalizados y políticas de validación
fields:
  milestone:
    type: string
    required: false
  priority:
    type: string
    enum: ["Low", "Medium", "High", "Critical"]
    default: "Medium"
  automated:
    type: boolean
    default: false

# Configuración por Alcance (scopes): identidad, convenciones y directorios
scopes:
  testcase:
    identity: "tc-*"
    convention: "{slug}.case.feature"
    output_dir: "./tests/cases"
  testrun:
    identity: "tr-*"
    convention: "{YYYYMMDD}_{HHmmss}.run.feature"
    output_dir: "./tests/runs"
  testplan:
    identity: "tp-*"
    convention: "{slug}.plan.feature"
    output_dir: "./tests/plans"
```

---

## Bloques de Configuración

### Bloque `provider`
Permite declarar el proveedor remoto en formato de diccionario estructurado o modo local:
- `github:` o `gitlab:`: Bloque del proveedor con sus credenciales y coordenadas del repositorio (`owner`, `repository`, `tokenEnv`, etc.).
- `local`: Indicador directo `provider: local` para operar únicamente en el archivo de estado local sin sincronización en la nube.
- `custom:`: Para proveedores personalizados registrados por el usuario.

### Bloque `scopes`
Configura las reglas para cada nivel del modelo (`testcase`, `testrun`, `testplan`):
- `identity`: Patrón de coincidencia para la etiqueta de identidad obligatoria (por defecto `tc-*`, `tr-*` y `tp-*` si se omite). También se acepta `match:`.
- `convention`: Patrón de nomenclatura automática utilizado por las herramientas de scaffolding (`{slug}`, `{YYYYMMDD}_{HHmmss}`).
- `output_dir`: Directorio por defecto donde se ubican o generan los archivos.

### Bloque `backend`
Configura la persistencia del estado y el bloqueo distribuido:
- `local`: Guarda `./testform.state` en el sistema de archivos local.
- `s3`: AWS S3 con bloqueos de estado en DynamoDB.
- `azurerm`: Azure Blob Storage con arrendamientos (Blob Leases).
- `gcs`: Google Cloud Storage con verificación de generación atómica.

### Bloque `fields`
Define el esquema de campos personalizados permitidos a partir de las variables de paso Gherkin (`* clave = valor`). Testform valida los tipos de datos y los valores permitidos (enums) durante la ejecución de `testform validate`.
