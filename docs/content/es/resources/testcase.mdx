# Recurso: testcase

El recurso `testcase` constituye el bloque fundamental de construcción en Testform. Cada `Scenario` Gherkin individual dentro de un archivo de testcase equivale a un Issue independiente creado y sincronizado en GitHub (o en tu Provider configurado).

---

## Reglas de Coincidencia de Archivos

Testform reconoce archivos de casos de prueba mediante cualquiera de las siguientes condiciones:
1. Archivos con terminación `.case.feature` (por ejemplo: `login.case.feature`).
2. Cualquier archivo `.feature` que contenga la etiqueta `@testcase` a nivel de `Feature:`.

---

## Ejemplo de Definición de Recurso

```gherkin
@testcase @auth @regression
Feature: Escenarios de Autenticación

  Background:
    * milestone = "Sprint 42"
    * assignees = "qa-lead"

  @smoke @tc-1
  Scenario: Credenciales válidas permiten el inicio de sesión
    Given el usuario navega a "/login"
    When el usuario ingresa credenciales válidas
    Then el usuario es redirigido a "/dashboard"
```

---

## Mapeo hacia el Provider (Ejemplo con GitHub)

Cuando Testform aplica este escenario, el Provider de GitHub lo traduce a un Issue con los siguientes atributos:

| Elemento Gherkin | Atributo en GitHub Issue | Valor Generado |
| :--- | :--- | :--- |
| **Título del Escenario** | **Título del Issue** | `Credenciales válidas permiten el inicio de sesión` |
| **Pasos** (`Given`/`When`/`Then`) | **Cuerpo del Issue (Markdown)** | Bloque de código Markdown con la secuencia exacta de pasos. |
| **Etiquetas** (`@auth`, `@regression`, `@smoke`) | **Etiquetas (Labels)** | `auth`, `regression`, `smoke` (las etiquetas `@testcase` y `@tc-1` se filtran). |
| **Etiqueta de Identidad** (`@tc-1`) | **Identificador en el Estado** | `login.case.feature::@tc-1` (registrado en `testform.state`). |
| **Variable DSL** (`* milestone`) | **Milestone** | Asocia "Sprint 42" con el ID del Milestone en GitHub. |
| **Variable DSL** (`* assignees`) | **Asignados** | Asigna la incidencia a `@qa-lead`. |

---

## Gestión de Recursos Testcase

```bash
# Previsualizar cambios en todos los casos de prueba
testform plan -scope=testcase

# Aplicar cambios de forma idempotente
testform apply -scope=testcase

# Destruir todos los casos de prueba (cierra los issues respectivos)
testform destroy -scope=testcase
```
