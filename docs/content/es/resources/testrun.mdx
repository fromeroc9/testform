# Recurso: testrun

Un recurso `testrun` representa un **ciclo de ejecución de pruebas** (como una regresión nocturna, certificación de release o prueba de humo).

A diferencia de un `testcase` (donde cada escenario es un issue independiente), un `testrun` compila el **archivo `.feature` completo en un único Issue principal**, el cual integra listas de verificación en tiempo real y tablas resumen de resultados.

---

## Reglas de Coincidencia de Archivos

1. Archivos con terminación `.run.feature` (por ejemplo: `sprint42.run.feature`).
2. Cualquier archivo `.feature` que contenga la etiqueta `@testrun` a nivel de `Feature:`.

---

## Ejemplo de Definición de Recurso

```gherkin
@testrun @tr-42
Feature: Ejecución de Regresión Sprint 42

  Background:
    * milestone = "Sprint 42"
    * assignees = "qa-lead"

  # Selección explícita de Escenarios
  Rule: authentication.case.feature
    Scenario: @tc-1
      * link status = passed

    Scenario: @tc-2
      * link status = failed
      * notes = "Falla en Safari con error de timeout"

  # Inclusión implícita: importa TODOS los casos de prueba de checkout.case.feature
  Rule: checkout.case.feature
```

---

## Cómo Renderiza Testform las Ejecuciones de Prueba

Al aplicar un `testrun`, Testform realiza las siguientes operaciones:
1. **Creación del Issue Principal**: Genera un issue titulado `"Ejecución de Regresión Sprint 42"`.
2. **Listas de Verificación Dinámicas**: Inyecta una lista Markdown con enlaces directos a los IDs reales de los testcases asociados:
   ```markdown
   ### Casos de Prueba Ejecutados
   - [x] #101 Authentication Scenarios: Valid credentials allow login
   - [ ] #102 Authentication Scenarios: Invalid credentials show error
   - [ ] #103 Checkout: Empty cart notification
   ```
3. **Comentarios de Ejecución**: Publica tablas estructuradas con metadatos de ejecución (`execution_time`, `runner`, `status`, trazas de error).

---

## Automatización de Ejecución con testform suite

Para mantener el principio de **Única Fuente de la Verdad (SSOT)** en el código local sin desfasar el estado remoto, las operaciones de autocompletado, enlace y marcado de resultados se realizan mediante el comando especializado `testform suite`:

### 1. Expansión de Reglas con `suite fill`
Si importaste un archivo completo mediante `Rule: checkout.case.feature` sin detallar escenarios individuales, puedes expandirlos automáticamente a escenarios explícitos en tu archivo local ejecutando:

```bash
testform suite fill -target="@tr-42"
```
Esto inspecciona el archivo `.case.feature` referenciado y añade cada escenario explícitamente a tu `.run.feature` con el estado inicial `* link status = pending`, permitiendo a los ejecutores de pruebas registrar resultados específicos.

### 2. Enlace de Casos con `suite link`
Para vincular casos de prueba dentro de tu testrun (ya sea de forma implícita o explícita):

```bash
# Enlace implícito: Vincula todo el archivo de casos
testform suite link "checkout.case.feature" -target="@tr-42"

# Enlace explícito: Vincula un caso puntual
testform suite link "@tc-1" -target="@tr-42"
```

### 3. Marcado de Resultados con `suite mark`
Para actualizar resultados desde pipelines de CI/CD o ejecutores de pruebas automáticos (Playwright, Cypress, Vitest, Jest) sincronizando el archivo `.run.feature` local y el issue del proveedor remoto de forma coherente, utiliza `testform suite mark`:

```bash
# Estrategia 1: Solo Tag (resuelve automáticamente dentro del testrun si es único)
testform suite mark "@tc-1=passed" -target="@tr-42"

# Estrategia 2: Archivo + Tag (desambigua cuando varios archivos comparten el mismo número de caso)
testform suite mark "checkout.case.feature::@tc-1=failed" -target="@tr-42"

# Estrategia 3: Nombre o Título del Escenario
testform suite mark "Pago con tarjeta de crédito exitoso=passed" -target="@tr-42"
```

> [!NOTE]
> `testform apply` se reserva estrictamente para la **conciliación declarativa** idempotente entre tus archivos locales y el proveedor remoto. No muta estados imperativamente fuera de banda, preservando la trazabilidad de Git.
