# Configure Providers

Los **Providers** en Testform son plugins modulares desacoplados que conectan la especificación declarativa de pruebas con las **plataformas de gestión de calidad y estado** (GitHub Issues / Projects, GitLab, Jira o Ledger Local).

Al igual que en Terraform un provider gestiona la comunicación con la API de un proveedor de nube (AWS, Azure, GCP) para registrar el estado de la infraestructura, en Testform un provider gestiona la comunicación con el issue tracker o el almacenamiento de estado para **crear, actualizar, cerrar y versionar casos de prueba y ejecuciones como código en Git**.

> [!IMPORTANT]
> **Diferencia Clave: Providers vs Test Runners**  
> - **Provider (`provider`):** Plataforma de gestión y trazabilidad donde residen los casos de prueba y el ledger de estado (`local`, `github`, `gitlab`, `jira`).  
> - **Test Runner:** Motor de automatización que ejecuta el código en navegadores, APIs o sockets (`Playwright`, `Cypress`, `Supertest`, `K6`).

---

## Declaración en `testform.yml`

Los providers se configuran en el archivo principal `testform.yml`:

```yaml
version: "1.0"

# Provider activo para el ciclo de vida de los casos y el ledger de estado
provider: "github" # o "local", "gitlab", "jira"

github:
  owner: "mi-organizacion"
  repo: "mi-sistema-web"
  project_number: 12 # GitHub Projects v2
  labels:
    testcase: "testcase"
    testrun: "testrun"
    testplan: "testplan"
```

## Providers Disponibles

| Provider | Tipo de Almacenamiento | Uso Recomendado |
|---|---|---|
| **`local`** | Archivo JSON local `testform.state` | Proyectos ágiles, pruebas locales y suites autónomas en Git sin dependencias externas. |
| **`github`** | GitHub Issues + GitHub Projects (GraphQL) | Equipos que centralizan sus especificaciones y ejecuciones en GitHub Enterprise / Cloud. |
| **`gitlab`** | GitLab Issues + Scoped Labels | Pipelines de GitLab CI/CD con trazabilidad en tableros de GitLab. |
| **`custom`** | Conectores HTTP / Webhook | Integraciones a medida con herramientas propietarias de QA o TestRail/Xray. |

## Inicialización del Provider (`testform init`)

Antes de ejecutar un plan, `testform init` autentica y valida el provider configurado:

```bash
testform init
```

Durante el `init`:
1. Verifica las credenciales de acceso (tokens de entorno como `GITHUB_TOKEN` o `GITLAB_TOKEN`).
2. Configura el backend de estado y el archivo de bloqueo concurrente (`.lock`).
3. Comprueba el acceso al repositorio y a los tableros del proyecto.
