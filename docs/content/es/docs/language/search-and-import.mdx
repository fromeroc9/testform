# Search and Import (Búsqueda e Importación)

Testform incluye capacidades completas para **descubrir, consultar e importar recursos** que fueron creados externamente o que residen en el ledger de estado, equivalente a la sección **Search and Import** de Terraform.

---

## 1. Búsqueda y Consulta de Recursos (`testform query`)

El comando `testform query` permite inspeccionar, filtrar y auditar los recursos declarados y los resultados de ejecución almacenados en `testform.state`.

### Sintaxis
```bash
testform query [opciones]
```

### Opciones de Filtrado Avanzado

| Flag | Descripción | Ejemplo |
|---|---|---|
| `--scope` | Filtra por tipo de recurso (`testcase`, `testrun`, `testsuite`) | `testform query --scope=testrun` |
| `--status` | Filtra por estado de ejecución (`passed`, `failed`, `skipped`) | `testform query --status=failed` |
| `--label` | Filtra por etiqueta o tag Gherkin | `testform query --label=@smoke` |
| `--assignee` | Filtra por usuario asignado en el proveedor | `testform query --assignee=flavio` |
| `--milestone` | Filtra por hito o versión de entrega | `testform query --milestone=v1.0` |
| `--custom` | Filtra por campos personalizados (`clave=valor`) | `testform query --custom=priority=high` |
| `--search` | Búsqueda por texto libre en títulos y descripciones | `testform query --search="checkout"` |
| `--count` | Retorna únicamente el número total de coincidencias | `testform query --status=failed --count` |
| `--json` | Salida estructurada en JSON para scripts de CI/CD | `testform query --json` |

### Ejemplo: Auditoría de Pruebas Fallidas
```bash
testform query --status=failed --scope=testcase
```
```text
Query Results:
  - checkout.feature::pay_test | Status: failed | Priority: high
Total: 1 resource(s) found.
```

## 2. Importación de Recursos Preexistentes (`testform import`)

El comando `testform import` permite adoptar casos de prueba o incidencias preexistentes (por ejemplo: Issues de GitHub o tickets de GitLab creados manualmente antes de usar Testform) dentro del ledger de estado **sin borrarlos ni duplicarlos**.

### Sintaxis
```bash
testform import -scope=<tipo> <direccion_local> <id_remoto>
```

### Ejemplo: Importar un Issue Existente de GitHub
Supongamos que en GitHub existe el Issue `#104` ("Login con certificado digital") y deseas gestionarlo desde Testform con el tag `@tc-5`:

```bash
testform import -scope=testcase "auth/login.case.feature.@tc-5" 104
```

### Flujo de Ejecución:
1. Testform consulta la API del proveedor (GitHub, GitLab, etc.).
2. Valida la existencia y el estado actual de la incidencia.
3. Extrae su título, etiquetas, asignados y atributos.
4. Registra el recurso en `testform.state` vinculándolo con la dirección `auth/login.case.feature.@tc-5`.
5. Ejecutas `testform plan` para verificar que el código local coincide con el estado importado con cero diferencias (*drift* cero).

```text
github_testcase.auth_login_case_feature__tc_5: Importing from ID "104"...
github_testcase.auth_login_case_feature__tc_5: Import prepared!
  Prepared github_testcase for import on auth/login.case.feature.@tc-5

Import successful!
These resources are now in your Testform state and will henceforth be managed
by Testform.
```
