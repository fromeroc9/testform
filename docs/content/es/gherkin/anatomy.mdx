# Anatomía de un Archivo Feature

Cada archivo Gherkin gestionado por Testform se compone de elementos estructurales estándar. Comprender cómo se proyecta cada componente hacia el Provider es clave para estructurar pruebas sólidas.

---

## Ejemplo Completo

```gherkin
@testcase @authentication @regression
Feature: Autenticación de Usuarios y Gestión de Sesión
  Como usuario registrado
  Quiero autenticarme de forma segura
  Para acceder a mi panel principal de control

  Background:
    * milestone = "Sprint 42"
    * assignees = "qa-lead"
    Given el servicio de autenticación se encuentra operativo
    And la base de datos contiene credenciales activas

  @critical @tc-1
  Scenario: Login exitoso con correo y contraseña válidos
    Given el usuario navega a "/login"
    When el usuario ingresa el correo "usuario@ejemplo.com"
    And el usuario ingresa la contraseña "Secreto123!"
    And el usuario presiona el botón "Iniciar Sesión"
    Then el sistema redirige hacia "/dashboard"
    And el encabezado muestra "¡Bienvenido, Juan!"

  @medium @tc-2
  Scenario: Login fallido con contraseña incorrecta
    Given el usuario navega a "/login"
    When el usuario ingresa el correo "usuario@ejemplo.com"
    And el usuario ingresa la contraseña "ClaveErronea"
    And el usuario presiona el botón "Iniciar Sesión"
    Then el sistema muestra el error "Credenciales no válidas"
```

---

## Desglose de Elementos Clave

### 1. La Palabra Clave `Feature:`
La declaración principal a nivel de archivo.
- **Etiquetas (Tags)**: Las etiquetas colocadas sobre `Feature:` (por ejemplo, `@authentication @regression`) son heredadas por **todos** los escenarios del archivo.
- **Identificador de Alcance (Scope)**: `@testcase`, `@testrun` o `@testplan` define qué tipo de recurso gestiona este archivo.
- **Descripción**: El texto multilinea bajo el título del feature se extrae como resumen y contexto documental.

### 2. El Bloque `Background:`
Se ejecuta antes de cada Escenario del archivo.
- **Precondiciones**: Pasos `Given` estándar que determinan un estado base.
- **Variables DSL**: Asignaciones `* clave = valor` para declarar valores de campos compartidos (por ejemplo, `* milestone = "Sprint 42"`).

### 3. El Bloque `Scenario:`
Un caso de prueba ejecutable individual.
- **Título**: Se convierte en el título del recurso remoto gestionado (por ejemplo, el título del Issue en GitHub).
- **Etiqueta Única de Identidad (`@tc-1`, `@tc-2`)**: El ancla de identidad permanente de Testform (equivalente al identificador lógico de un recurso en Terraform). Es obligatoria bajo la policy `identity-required`, garantizando que si renombras el escenario, Testform actualice el issue remoto in-place en vez de duplicarlo, y permitiendo que los `testruns` referencien el caso de prueba con exactitud.
- **Pasos**: Secuencia de sentencias `Given`, `When`, `Then`, `And`, `But`.

### 4. La Palabra Clave `Rule:`
Ampliamente utilizada en archivos `testrun` para agrupar casos de prueba por reglas de negocio o vincular archivos `.case.feature` externos:
```gherkin
  Rule: checkout.case.feature
    Scenario: @tc-1
      * link status = passed
```
