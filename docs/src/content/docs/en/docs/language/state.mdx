# State (State Ledger & Management)

The **State (`testform.state`)** is the authoritative ledger mapping your declarative test specifications to the physical execution reality and attributes of each test run.

Just as Terraform's state file tracks IDs of created cloud instances, Testform's state records test execution identifiers, content hashes for drift detection, pass/fail status, and generated outputs.

---

## State Ledger File (`testform.state`)

The state is a structured JSON ledger maintained after every `testform apply`:

```json
{
  "version": "1.0.0",
  "testform_version": "1.0.17",
  "serial": 12,
  "resources": [
    {
      "address": "auth/login.feature.@login_success",
      "type": "testcase",
      "name": "login_success",
      "status": "passed",
      "hash": "a1b2c3d4...",
      "attributes": {
        "title": "Successful user login",
        "duration_ms": 1420
      }
    }
  ],
  "outputs": {
    "login_title": {
      "value": "Successful user login",
      "type": "string"
    }
  }
}
```

---

## Distributed State Locking (`testform.state.lock`)

To prevent race conditions and state corruption when multiple engineers or parallel CI/CD runners access the same repository, Testform enforces **atomic state locking**:

1. Before starting a plan or execution, Testform acquires an exclusive lock (`testform.state.lock`).
2. The lock records process ID (PID), user, hostname, and timestamp.
3. If another process attempts to access the locked state:
```text
[ERROR] Error acquiring the state lock:
  Lock Info:
    ID:        a9b8c7-lock
    Path:      testform.state
    Operation: OperationTypeApply
    Who:       runner-1@ci-node-4
    Created:   2026-10-24 17:15:00 UTC
```

## Drift Detection

During reconciliation (`testform refresh` or `testform plan`):
- Testform evaluates cryptographic checksums of each scenario's source steps.
- If physical execution results or local code have drifted from the state ledger, an update diff (`~ update`) is planned.
- Silent regressions or modified assertions are surfaced immediately before execution.
