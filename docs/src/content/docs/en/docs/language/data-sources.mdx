# Data Sources (`data:`)

**Data Sources** in Testform allow your test specifications and configuration blocks to reference external, read-only data fixtures or previously managed resources, mirroring Terraform's `data` block.

With `data:`, you can:
1. **Load external datasets and fixtures (`file`)**: Inject structured data from external JSON or YAML files (`fixtures/users.json`, `data/payments.yml`) into Gherkin steps, local variables, and outputs.
2. **Reference existing resources (`address`)**: Query remote IDs, titles, tags, or custom fields from other test cases without duplicate declarations.

---

## Declaration in `data.yml` or `main.yml`

Data sources are defined under the `data:` block in `data.yml`, `main.yml`, or domain files:

```yaml
# data.yml
data:
  # Mode 1: Loading external fixture files
  users:
    file: "fixtures/users.json"

  # Mode 2: Referencing existing resource by address
  login_core:
    address: "auth/login.case.feature.@tc-1"
```

---

## Data Source Modes

### 1. Fixture File Mode (`file`)
Loads structured JSON or YAML datasets:

**`fixtures/users.json`**:
```json
{
  "admin": {
    "username": "admin@company.com",
    "role": "SuperAdmin"
  }
}
```

In your Gherkin scenario:
```gherkin
Scenario: Admin authentication flow
  Given user navigates to login portal
  When user fills in username "${data.users.admin.username}"
  Then active role is displayed as "${data.users.admin.role}"
```

### 2. Address Mode (`address`)
Enables querying metadata of existing test resources:

```gherkin
Scenario: Validate authentication prerequisite
  Given prerequisite test "${data.login_core.title}" has passed
  Then proceed with checkout verification
```

---

## Interpolation Syntax

Data source attributes are interpolated using `${data.<source>.<property>}`:

- `${data.users.admin.username}` $\rightarrow$ Resolves to the `username` field inside `admin`.
- `${data.login_core.address}` $\rightarrow$ Resolves to the canonical resource address.
- Expressions are evaluated during compilation and previewed in `testform plan`.
