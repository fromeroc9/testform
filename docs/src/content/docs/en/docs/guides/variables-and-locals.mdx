# Variables and Local Values (5-Level Hierarchy)

Testform implements a variable (`vars:`) and local values (`local:`) resolution engine inspired by Terraform, but adapted to the native readability of **YAML**.

No `.tfvars` or JSON files required: **everything is declared and resolved in YAML**.

---

## 1. Declaration: `vars:` vs `local:`

### The `vars:` Block (Input Variables)
Variables represent configurable input parameters declared with metadata:

```yaml
vars:
  app_url:
    type: string
    description: "Base URL for the test environment"
    default: "https://www.saucedemo.com"
  environment:
    type: string
    description: "Target environment (dev, staging, prod)"
    default: "dev"
  default_timeout:
    type: number
    default: 5000
```

Referenced in `.feature` files via:
`${var.variable_name}`

### The `local:` Block (Local and Computed Values)
Locals represent derived constants or computed expressions to prevent code duplication:

```yaml
local:
  base_url: "${var.app_url}"
  login_url: "${local.base_url}"
  api_health: "${local.base_url}/health"
  tag_env: "@env-${var.environment}"
```

Referenced via:
`${local.local_name}`

Testform resolves transitive dependencies (locals referencing other locals or variables) through multiple evaluation passes.

## 3. Usage in Gherkin Feature Files (`.case.feature`)

Variables and locals are interpolated seamlessly in both **tags** and **steps**:

```gherkin
@testcase
Feature: User Authentication in SauceDemo
  @tc-1 @auth @smoke ${local.tag_env}
  Scenario: Successful login with standard user
    Given the user navigates to "${local.login_url}"
    When entering username "standard_user"
    And entering password "secret_sauce"
    And clicking the "Login" button
    Then the system redirects to "${var.app_url}/inventory.html"
```
