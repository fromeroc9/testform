# Migration from Spreadsheets

Transform legacy spreadsheet test inventories (Excel, CSV, Google Sheets) into version-controlled Git assets with Testform.

## Legacy Spreadsheets vs Declarative Test-as-Code

In manual spreadsheets, tests are typically modeled across tabular columns:
- Test ID (`TC-01`)
- Title / Summary
- Preconditions
- Execution Steps
- Expected Outcome

### Spreadsheet Row Example

| ID | Title | Precondition | Steps | Expected Outcome |
| :--- | :--- | :--- | :--- | :--- |
| `TC-101` | Password Reset | Registered user | 1. Go to /forgot 2. Enter email 3. Submit | Email received with reset token |

## Conversion to `.feature` Specification

Author the corresponding file `tests/features/password_reset.case.feature`:

```gherkin
@tc-password-reset-101
@priority-medium @component-auth
Feature: User Password Recovery
  As a registered user who forgot their password
  I want to request a recovery link
  In order to regain secure access to my account

  Scenario: Successful password reset email dispatch
    Given the user navigates to the URL "/forgot"
    When the user submits email "registered@company.com"
    And clicks "Send Recovery Link"
    Then the system displays "Check your inbox for further instructions"
    And a reset email is dispatched containing a 15-minute validity token
```

## Incremental Migration Strategy

You do not need to convert your entire testing catalog overnight:
1. Start by migrating critical `@smoke` test cases.
2. Execute `testform plan` and `testform apply` to establish your initial state ledger.
3. Progressively migrate regression test suites over future development sprints.
