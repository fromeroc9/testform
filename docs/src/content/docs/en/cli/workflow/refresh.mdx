# `testform refresh`

```bash
testform [global options] refresh [options]
```

The `testform refresh` command reads the current reality from remote Provider APIs and updates `testform.state` to match. 

It does **not** modify remote infrastructure, nor does it update local `.feature` files. It reconciles out-of-band changes (e.g. issues closed manually in the web UI, or labels updated outside of Testform).

## Real Execution Example

```bash
$ testform refresh

github_testcase.login_valid: Refreshing state... [id=104]
github_testcase.checkout_coupon: Refreshing state... [id=105]

State refreshed successfully.
```

If an issue was manually closed in GitHub, `testform refresh` records `state: "closed"` in `testform.state`. A subsequent `testform plan` will then show:

```bash
~ resource "testcase" "login_valid" {
    ~ state = "closed" -> "open"
  }
```

## Exit Codes

- `0`: State refreshed successfully.
- `1`: Network or authentication error contacting Provider APIs.
