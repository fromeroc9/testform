## 2. Registro de Nuevos Proveedores (Custom Providers)

Para conectar Testform con plataformas externas (Jira, TestRail, Zephyr o herramientas propietarias), se registran recursos adicionales mediante la misma API pÃºblica:

```typescript

    type: 'jira_testcase',

            name: 'description', 
            value: (s) => s.steps.map(st => `${st.keyword} ${st.text}`).join('\n') 
        },
        { 
            name: 'priority', 
            value: (s) => s.custom?.fields?.priority || 'Medium' 
        }
    ]
});
```

## 3. Direcciones CanÃ³nicas de Recursos (Resource Addresses)

Al igual que en Terraform cada recurso posee un identificador universal Ãºnico (ej. `aws_instance.web`), en Testform cada recurso se direcciona mediante **notaciÃ³n por puntos pura**:


Ejemplos:
- `features/auth/login.case.feature.@tc-001`

Estas direcciones son utilizadas por:
- El motor de dependencias `@depends_on("features/auth/login.case.feature.@tc-001")`
- El ledger inmutable de estado `testform.state`
- Comandos CLI como `testform state show <address>` y `testform taint <address>`
